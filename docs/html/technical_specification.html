SVG to GCode Converter - Technical Specification

Overview

This document details the technical specifications for the SVG to GCode converter application, focusing on API definitions, data models, and key algorithms as they are currently implemented in the codebase.

Data Models

1. SVG Input Representation

The SVG input is represented as parsed data from the svg-parser library. The SVGProcessor converts this into an internal representation:

// Internal SVG representation
{
  paths: [
    {
      id: String,                   // Path identifier
      type: String,                 // Path type (line, rect, circle, path, etc.)
      segments: Array,              // Path segments
      style: {                      // Style properties
        fill: String,               // Fill color
        stroke: String,             // Stroke color
        strokeWidth: Number,        // Stroke width
        grayscaleValue: Number      // Computed grayscale value (0-255)
      },
      bounds: {                     // Path bounds
        minX: Number,
        minY: Number,
        maxX: Number,
        maxY: Number,
        width: Number,
        height: Number
      }
    }
  ],
  viewBox: {                        // SVG viewBox attributes
    minX: Number,
    minY: Number,
    width: Number, 
    height: Number
  },
  size: {                           // SVG dimensions
    width: Number,
    height: Number
  }
}

2. Toolpath Representation

Toolpaths are represented as a collection of points with associated depth values:

// Toolpath representation
{
  toolpaths: [
    {
      id: String,                   // Toolpath identifier
      type: String,                 // Toolpath type
      points: [                     // Array of 3D points
        {
          x: Number,                // X coordinate
          y: Number,                // Y coordinate
          z: Number,                // Z coordinate (depth)
          penUp: Boolean            // Whether tool is raised
        }
      ],
      depth: Number,                // Maximum depth value
      color: String                 // Visual representation color
    }
  ],
  config: Object                    // Configuration used for generation
}

3. GCode Output Model

// Final GCode output
{
  header: String[],                 // Array of header commands/comments
  commands: String[],               // Array of GCode commands
  footer: String[],                 // Array of footer commands
  metadata: {                       // Additional metadata
    minDepth: Number,               // Minimum cutting depth
    maxDepth: Number,               // Maximum cutting depth
    totalPaths: Number,             // Number of paths processed
    estimatedTime: Number           // Estimated machining time (seconds)
  },
  estimatedTime: Number             // Estimated machining time
}

4. Configuration Model

// Configuration object
{
  machine: {                        // Machine configuration
    flavor: String,                 // GCode flavor ('grbl', 'marlin', etc.)
    feedRates: {                    // Feed rates in mm/min
      default: Number,              // Default feed rate
      plunge: Number,               // Plunge feed rate
      rapid: Number                 // Rapid feed rate
    },
    safeHeight: Number,             // Safe travel height (mm)
    workArea: {                     // Work area dimensions
      width: Number,                // Width (mm)
      height: Number                // Height (mm)
    }
  },
  tool: {                           // Tool configuration
    diameter: Number,               // Tool diameter (mm)
    spindleSpeed: Number            // Spindle speed (RPM)
  },
  grayscaleMapping: {               // Grayscale mapping configuration
    type: String,                   // Mapping type ('linear', 'custom')
    maxDepth: Number,               // Maximum cutting depth (mm)
    minDepth: Number,               // Minimum cutting depth (mm)
    invert: Boolean                 // Whether to invert depth mapping
  },
  output: {                         // Output configuration
    includeHeader: Boolean,         // Include header comments
    includeFooter: Boolean,         // Include footer comments
    precision: Number               // Decimal precision
  }
}

Algorithm Specifications

1. Grayscale to Depth Mapping Algorithm

The grayscale to depth mapping algorithm is implemented in the SVG Processor's _calculateGrayscale method and is used to convert grayscale values (0-255) to physical depth values (in mm) for CNC machining.

 * Calculate grayscale value from fill color

 * @returns {number} - Grayscale value (0-255)
 */

  // Return value between 0-255
}

/**
 * Map grayscale value to depth
 * @param {number} grayscale - Grayscale value (0-255)
 * @param {Object} config - Grayscale mapping configuration
 * @returns {number} - Depth value in mm
 */
mapGrayscaleToDepth(grayscale, config) {
  const { minDepth, maxDepth, invert } = config.grayscaleMapping;
  const normalizedValue = grayscale / 255;
  
  // If inverted, darker colors will be higher (less deep)
  if (invert) {
    return minDepth + (maxDepth - minDepth) * normalizedValue;
  } else {
    return minDepth + (maxDepth - minDepth) * (1 - normalizedValue);
  }
}

2. Path Optimization Algorithm

The path optimization algorithm is implemented in the Path Generator to reorder paths to minimize non-cutting travel distance and time.

/**
 * Optimize paths to minimize travel distance
 * @param {Array} paths - Array of paths
 * @returns {Array} - Optimized paths
 */
optimizePaths(paths) {
  // Start from current position (0,0)
  let currentPosition = { x: 0, y: 0 };
  const optimizedPaths = [];
  const remainingPaths = [...paths];
  
  while (remainingPaths.length > 0) {
    // Find nearest path
    const nearestIndex = this._findNearestPathIndex(currentPosition, remainingPaths);
    const nextPath = remainingPaths.splice(nearestIndex, 1)[0];
    
    // Add to optimized paths
    optimizedPaths.push(nextPath);
    
    // Update current position to end of path
    const lastPoint = nextPath.points[nextPath.points.length - 1];
    currentPosition = { x: lastPoint.x, y: lastPoint.y };
  }
  
  return optimizedPaths;
}

3. Circle and Arc Fixing Algorithm

The circle and arc fixing algorithm is implemented in specialized utilities to correct issues with circular elements in SVG files.

/**
 * Fix arcs and circles in SVG for better toolpath generation
 * @param {Array} paths - Array of paths
 * @returns {Array} - Fixed paths
 */
fixCirclesAndArcs(paths) {
  return paths.map(path => {
    if (path.type === 'circle' || path.type === 'arc') {
      return this._fixCircularPath(path);
    }
    return path;
  });
}

4. GCode Generation for GRBL

The GRBL-specific GCode generation algorithm is implemented in the GCode Generator to create commands optimized for GRBL controllers.

/**
 * Generate GRBL-compatible GCode
 * @param {Object} toolpaths - Toolpath data
 * @param {Object} config - Configuration
 * @returns {string} - Generated GCode
 */
generateGRBL(toolpaths, config) {
  const commands = [];
  
  // Add header
  commands.push(...this._generateGRBLHeader(config));
  
  // Process each toolpath
  toolpaths.forEach(toolpath => {
    commands.push(...this._processToolpath(toolpath, config));
  });
  
  // Add footer
  commands.push(...this._generateGRBLFooter(config));
  
  return commands.join('\n');
}

Error Handling

The application implements error handling primarily through try-catch blocks in the main processing methods. Errors are logged to the console and in some cases are displayed to the user through dialog boxes.

try {
  // Process SVG data
  if (progressCallback) progressCallback(10);
  console.log("Processing SVG data...");
  const processedData = await this.getProcessedData(svgData, config);
  
  // Additional processing...
} catch (error) {
  console.error('Error converting SVG to GCode:', error);
  throw error;
}
